# `task_geometry_measurement_value`

## 1) Identity
1. Domain: `geometry`
2. Task group: `measurement`
3. Task id: `task_geometry_measurement_value`
4. Objective: measure one requested geometric quantity from a single labeled scene.

## 2) Scene + task contract
1. Supported `scene_variant` values:
   - `angle`
   - `segment`
   - `triangle`
   - `quadrilateral`
   - `pentagon`
   - `circle`
   - `ellipse`
   - `line`
2. Supported `query_variant` values:
   - `angle`
   - `length`
   - `area`
   - `perimeter`
   - `slope`
3. Supported pairings:
   - `angle` + `angle`
   - `segment|triangle|quadrilateral|pentagon|circle|ellipse` + `length`
   - `triangle|quadrilateral|ellipse` + `area`
   - `triangle|quadrilateral|circle` + `perimeter`
   - `line` + `slope`
4. Answer types vary by compatible pair:
   - `integer`
   - `decimal`
   - `pi_expression`
5. Evidence types vary by compatible pair:
   - `graph_point`
   - `graph_point_set`
6. The consolidated task keeps the shape family in `scene_variant` and the requested measurement type in `query_variant`; pair-specific rendering/evidence still come from the legacy geometry measurement generators.

## 3) Prompt contract
1. Bundles remain legacy-generator-backed:
   - `geometry_angle_measure_v1`
   - `geometry_measurement_v1`
2. Prompt JSON examples and evidence hints stay pair-specific.
3. `query_spec.params` always records both consolidated axes:
   - `scene_variant`
   - `query_variant`
4. Legacy prompt metadata is preserved in trace under `legacy_*` fields for auditability.

## 4) Evidence + trace contract
1. `execution_trace` always includes:
   - `scene_variant`
   - `query_variant`
   - `scene_variant_probabilities`
   - `query_variant_probabilities`
   - `legacy_task_id`
2. `query_spec.params` mirrors the same consolidated fields.
3. `scene_ir.relations` also records the consolidated scene/query pair.
4. Evidence order is semantic only when required by the underlying legacy measurement contract.

## 5) Visual policy
1. Visual styling remains inherited from the legacy measurement scenes.
2. Consolidation does not change the legacy graph-paper rendering contracts; it changes task taxonomy and sampling only.

## 6) Determinism + constraints
1. Deterministic generation from `instance_seed`.
2. Incompatible `scene_variant` / `query_variant` pairs are rejected.
3. Answers and evidence still come from the same finalized scene trace generated by the legacy task implementation.

## 7) Complexity + tests
1. Complexity components stay measurement-family-specific and come from the delegated legacy generator.
2. Determinism/build tests: `tests/test_geometry_consolidated_contracts.py`
3. Behavior/trace tests: `tests/test_geometry_consolidated_tasks.py`
