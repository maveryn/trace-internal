# TRACE Shared Utilities

Use this document to prevent duplicate helper implementations.

## 1) Placement policy
Choose the narrowest reusable layer:
1. `trace/core/*` — cross-system infrastructure (hashing, seeds, validation, build).
2. `trace/tasks/shared/*` — cross-domain task logic.
3. `trace/tasks/<domain>/shared/*` — domain logic reused by multiple scenes.
4. `trace/tasks/<domain>/<scene_id>/shared/*` — scene primitives reused by
   multiple task objectives in one scene.
5. task-local module — objective-specific behavior for one public task.

Promote helpers when a second consumer appears.

Shared modules are for reusable primitives, not ownership of public objective
programs. A public scene-package task file must contain the necessary code for
its task-specific objective: target construction, answer binding,
prompt-facing annotation binding, prompt-slot assembly, and task-specific trace
payload. If multiple tasks in one scene share rendering, board construction,
layout, style, rule primitives, or annotation projection logic, keep that code
under `trace/tasks/<domain>/<scene_id>/shared/` and import it from the task
files. Do not move a multi-task generator into `shared/` and leave public task
modules as no-op wrappers that only force an objective name or call
`super().generate(...)`.

Good shared code:
1. renderer/style/layout helpers;
2. board or geometry dataclasses;
3. legal-move/rule primitive enumeration;
4. reusable annotation projection/artifact helpers;
5. deterministic support/query samplers that do not decide the public
   objective by task id.

Bad shared code:
1. a dispatcher that branches over multiple public task ids or objective
   contracts;
2. a scene generator that creates final `answer_gt`, `annotation_gt`, prompt
   payloads, and `TaskOutput` records for several public task files;
3. a base task class whose subclasses differ only by class attributes or a
   forced query/objective name.

## 3) Reuse rules
1. Do not duplicate deterministic utilities.
2. Prefer importing canonical helpers over wrappers.
3. Prefer shared canonical type aliases (for example `geometry_primitives.Point`) over equivalent local redefinitions.
4. Keep module `__all__` limited to externally consumed symbols.
5. Keep internal helper steps private until they have external consumers.
6. If shared APIs change, update docs in the same change.

## 4) Quick review checklist
1. Did we search shared modules first?
2. Is this helper at the right layer?
3. Are we exposing only needed public API?
4. Did we update docs that reference helper placement?
